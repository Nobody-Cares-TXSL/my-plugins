# Deep Read — 智能阅读助手

按文档类型自动选择压缩策略，去冗存真，输出可替代原文的精炼版。

## 获取内容

解析 $ARGUMENTS 决定输入方式：

- **以 http/https 开头** → URL，通过 agent-reach 抓取全文
- **其他** → 视为文件路径，用 Read 工具读取
- **无参数** → 提示用户提供内容或 URL/文件路径

## 文档类型识别

读取内容后，根据标题、路径、内容特征判断类型：

| 信号 | 类型 |
|------|------|
| 标题/路径含 `interview`、`八股`、`面试`、`面经`、`Q&A`、`FAQ` | **八股文** |
| 标题含 API、Reference、SDK 文档；掘金/CSDN 技术文 | **技术文档** |
| 内容涉及 LLM、提示工程、模型评测、RAG、Agent 架构 | **LLM 文档** |
| 文件为 `.py/.js/.ts/.go/.rs/.java` 等源码 | **代码文件** |
| 内容 < 500 字 | **短帖** |
| 以上都不匹配 | **通用文章** |

识别失败时回退到通用文章。

## 按类型处理

### 短帖

直接返回原文，不压缩。

### 代码文件

所有代码块统一处理：标注原文位置 + 文字概括，不原样输出。

- 格式：`> 💻 [代码简要标题]（`file:起始行-结束行`）— [代码做了什么、核心逻辑、关键设计点]`
- 核心实现（类/算法/关键函数）：概括含类名/函数名、核心方法、设计要点
- 配置/安装类代码：简要说明配置项
- 测试/示例代码：说明输入输出和验证目的

### 八股文

保留：
- 问答对（Q + A），A 只保留要点（关键词 + 结论）
- 关键代码片段（复用代码文件规则）

去掉：
- 背景铺垫、历史演进、过渡废话
- 同一知识点的重复问答

输出格式：保持原文 Q&A 结构，每个答案精炼为要点列表。

### 技术文档

保留：
- 接口/函数签名、参数表、返回值
- 行为描述（输入→输出）
- 代码示例（复用代码文件规则）
- 关键注意事项

去掉：
- 设计哲学和动机说明
- 问题背景、版本历史

输出格式：保持原文结构层次，精炼每个小节。

### LLM 文档

保留：
- 核心概念定义
- 架构/流程的文字描述
- 关键实验数据（模型、数据集、指标）
- 提示词模板和参数设置

去掉：
- LLM 发展历史和市场分析
- 入门级介绍（除非是概念首次定义）
- 冗长的相关工作对比

输出格式：保持原文结构，对核心概念用引用块做简要定义，实验数据保留表格或紧凑列表。

### 通用文章

通用文章走复杂度分级处理。

#### 复杂度判断

根据三个信号加权判断：

| 信号 | 低 | 中 | 高 |
|------|----|----|----|
| 术语密度 | 几乎无专业术语 | 偶有术语但上下文可推断 | 密集术语，不解释无法理解 |
| 推理层数 | 单层因果、线性叙述 | 2-3 层推理或分支逻辑 | 多层嵌套推理、反直觉结论 |
| 受众门槛 | 通用知识即可 | 需要领域基础背景 | 需要专家级背景 |

决策规则：
- 三个信号均为低 → **低**
- 任一信号为高 → **高**
- 其余 → **中**

#### 分级策略

- **低** — 纯压缩，去冗余保留骨架
- **中** — 压缩 + 核心概念穿插简短类比（1-2 句，融入正文）
- **高** — 压缩 + 类比 + 独立例子区块（篇幅 ≤ 原文 15%）

#### 辅助规则（仅通用文章）

**类比**：概念定义后紧跟 `> 类比：...`，1-2 句，用日常经验映射抽象概念。

**专业术语**：首次出现后用 `> **术语名**：大白话解释`，1-3 句，让零基础读者理解。

**循序渐进例子**（仅高复杂度）：选最核心流程，用具体实例走完全程，独立 `### 例子：[标题]` 区块。

## 全局规则

以下规则对所有文档类型生效：

**公式**：Claude Code CLI 无法渲染 LaTeX，全部转为纯文本：
- 简单公式用 ASCII（`π(q)` 代替 LaTeX）
- 复杂公式用文字描述直觉 + ASCII 关键变量
- 多行推导拆为文字步骤
- 禁止 `$$...$$` 等 LaTeX 标记

**图表**：仅当原文有实际图片 URL 或明确引用图表时处理：
- 格式：`> 📊 [图表标题] — [一句话说明]`
- 有 URL 时附上链接

## 输出格式

```
# [原文标题或主题]

> 类型：[八股文/技术文档/LLM文档/通用文章] ｜ 复杂度：[高/中/低] ｜ 来源：[URL/文件路径]

[精炼内容]
```

通用文章高复杂度时追加：
```
## 例子：[核心流程名]

[具体实例]
```

## 注意事项

- 精炼后的内容可替代原文使用，不引入原文未提及的知识
- 内容本身已足够精炼时（如短帖、摘要），说明后返回原文
- 代码块一律不原样输出
