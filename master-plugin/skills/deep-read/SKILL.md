# Deep Read — 智能阅读助手

将大段内容去冗存真，并在读者需要时用类比和例子辅助理解。读一遍输出即可获得接近通读原文的理解效果。

## 获取内容

解析 $ARGUMENTS 决定输入方式：

### 有参数时

- **以 http/https 开头** → URL，通过 agent-reach 抓取全文
- **其他** → 视为文件路径，用 Read 工具读取

### 无参数时

提示用户粘贴内容或提供 URL/文件路径。

## 处理流程

读取完整内容后，先评估复杂度，再按对应策略处理。

### 复杂度判断

评估内容复杂度（低/中/高），依据：
- 信息密度（技术术语、数据、逻辑链的密度）
- 内容深度（是否包含多层推理、隐含假设、反直觉结论）
- 主题新颖度（对目标受众而言的概念难度）

### 按复杂度分级处理

**低复杂度 — 纯压缩：**
- 去冗余、保留骨架，不加额外解释

**中复杂度 — 压缩 + 类比：**
- 在压缩基础上，对核心概念穿插简短类比（1-2 句，融入正文，不独立成节）

**高复杂度 — 压缩 + 类比 + 例子：**
- 在压缩基础上穿插类比，并针对最核心的流程/概念提供一个循序渐进的例子
- 例子独立成节，用具体实例走完全流程，篇幅控制在原文 10-15%

### 压缩规则

**核心原则：信息零丢失的前提下，尽可能短**

保留：
- 核心论点与关键信息（原文骨架）
- 完整的推理链和因果关系
- 具体数据、术语、定义、关键引用
- 原文的结构层次和逻辑走向

去掉：
- 重复表述（同一个观点换词再说）
- 过渡废话（"值得注意的是"、"综上所述"等空话）
- 冗余论据（已充分证明后继续堆叠的概念性例子）
- 不影响理解的修辞和修饰
- **代码块不原样输出**（见代码处理规则）

### 代码处理规则

**所有代码块统一处理方式：标注原文位置 + 文字概括，不原样输出。**

对于读取的文件路径来源：
- 格式：`> 💻 [代码简要标题]（`file:起始行-结束行`）— [代码做了什么、核心逻辑、关键设计点]`
- 如果是核心实现（类定义、核心算法、关键函数），概括需包含：类名/函数名、核心方法、设计要点
- 如果是配置/安装类代码，简要说明配置项即可
- 如果是测试/运行示例代码，说明输入输出和验证目的

对于 URL 来源（无行号）：
- 格式：`> 💻 [代码简要标题] — [代码做了什么、核心逻辑、关键设计点]`
- 附上原文对应小节标题供定位

### 类比编写规则

- 用日常经验、具象场景映射抽象概念
- 类比必须准确，不能误导
- 长度 1-2 句，不展开成段落
- 格式：概念定义后紧跟 `> 类比：...`

### 专业术语解释规则

- 对原文中出现的专业术语（尤其是首次出现时），用 `>` 引用块给出简明的入门级解释
- 解释要让零基础读者也能理解"这是什么"
- 控制在 1-3 句，不写成百科词条
- 格式：术语首次出现后紧跟 `> **术语名**：用大白话解释这是什么...`

### 图表引用处理

- 扫描原文中所有图片（包括显式引用如"如图 X.X 所示"以及未引用但存在的图片）
- 在输出中对应位置保留图表提示，简要说明图中展示了什么，提醒读者对照原文查看
- 格式：`> 📊 [图表标题或编号] — [一句话说明图中展示了什么]`
- 如果原文提供了图片 URL，附上链接方便直接查看

### 循序渐进例子规则（仅高复杂度）

- 选取一个最核心的流程/概念，用具体实例走完全程
- 简化具体（具体数字、具体句子），不用抽象符号
- 篇幅控制在原文 10-15%，不喧宾夺主
- 格式：独立的 `### 例子：[标题]` 区块

### 公式处理规则

输出环境（Claude Code CLI）无法渲染 LaTeX，所有公式必须转为终端可读的纯文本形式：

- **简单公式**：用 ASCII 符号替代 LaTeX（如 `π(q)` 代替 `$$\pi(q)$$`，`a_t, o_t` 代替 `a_t, o_t`）
- **复杂公式**：用纯文字描述直觉含义 + 关键变量的 ASCII 表达
- **多行推导**：拆为文字步骤说明，每步用缩进对齐
- **禁止输出**：`$$...$$`、`$\pi_{\text{xxx}}$` 等 LaTeX 标记（下标用 `π_solve` 而非 `$$\pi_{\text{solve}}$$`）
- 核心原则：公式存在的目的是传递"什么输入产生什么输出"的关系，纯文字说清楚这个关系即可

## 输出格式

低/中复杂度：

```
## [原文标题或主题]

> [复杂度：高/中/低]

[压缩内容，中复杂度时关键概念后穿插类比]
```

高复杂度：

```
## [原文标题或主题]

> [复杂度：高/中/低]

[压缩内容，关键概念后穿插类比]

### 例子：[核心流程名]

[用具体实例走一遍核心流程]
```

## 注意事项

- 理解辅助必须忠于原文：类比和例子只解释原文已有概念，不引入原文未提及的知识
- 压缩内容读起来仍是原文的精炼版，类比/例子是辅助而非替代
- 如果内容本身已经足够精炼（如推文、短消息），说明后原样返回
- 代码块一律不原样输出，用行号定位 + 文字概括替代
