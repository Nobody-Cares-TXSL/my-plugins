# 代码解释

解释用户指定的代码，用中文说明，保留技术术语原文。**默认产出一页 HTML 图解页面**；环境里拿不到渲染 CLI 时退化为结构化文本。

## 输入与工具

- Claude Code CLI：使用技能调用中的 `$ARGUMENTS`、选中的代码或用户给出的文件位置。
- Codex：使用用户消息中的代码片段、文件路径、行号或编辑器提供的选择上下文，不依赖 `$ARGUMENTS` 自动展开。
- 缺少明确的代码范围时询问用户，不自行选取整个仓库。
- 有文件位置时先读取对应源码，再按需查看 imports、类型和直接相关的调用方；粘贴片段没有来源时不要编造路径或行号。
- Claude Code CLI 优先使用 Read、Grep、Glob；Codex 使用当前环境提供的文件读取和搜索工具。复杂探索仅在需要且已获授权时使用可用的子代理工具，不依赖固定工具名称。

## 页面结构（必选，顺序固定）

1. **导语**：一两句给出这组代码在系统里的位置与职责。
2. **功能总览**：一张表列全范围内的**每一个声明**——interface、type、函数、类、类的每个字段与方法。每行写「种类 + 它干什么活、为谁存在」。这一节回答「每个东西是干什么的」，不能省。
3. **引用地图**：`flow` 图画出相关方如何连到本组代码；一张表列出外部落点（定义处、调用方、测试、契约文档、配置项），每行带核实过的 `file:line`。
4. **正文**：按文件顺序**全文引用**代码，逐块配三段：
   - **流程**：这几行在数据/控制链上干什么，输入是什么、结果去哪。
   - **语法**：把出现的 TS 符号逐个用大白话讲清（见下节）。
   - **引用**：这段依赖谁、被谁调用、哪条测试钉死了它。
5. **库函数清单**：只列代码**直接调用**的第三方或标准库函数，每个一句作用。

## 全文引用

- 用 ```` ```ts src=<相对路径> lines=<起>-<止> ```` 引用真实代码，不手抄、不改写。
- 范围是「全文」时，**从第 1 行开始**（含文件头注释），一直引到文件末行；不要从第一个声明才开始。漏掉的头注释往往写着依赖红线或边界约定，是理解前提。
- 同一文件分段引用时，段与段的区间要拼起来覆盖整份文件，不留缺口。
- 行号区间按实际内容裁，空行与孤立的收尾括号可以并入相邻块。
- 高亮 `hl=` 打在**这一块最关键的判断或赋值**那一行，一块只打一处。

## 语法说明

只解释 TS/JS 自身写法，**不做其它语言的对照**（不写「≈ Java final」「≈ C++ variant」之类）。

逐个符号说清三件事：它是什么意思、编译后还在不在、什么时候会踩坑。常见必讲项：

| 符号 | 要讲清 |
|---|---|
| `interface` / `type` | 只在编译期存在，运行时没有这个类；看形状不认名字 |
| `readonly` / `?:` | 只编译期拦赋值；`?` 表示键可整个省略 |
| `a \| b` | 联合类型，值只能是其中一种 |
| `{ type: 'x' } \| { … }` | 判别联合：按标签字段分派后自动窄化 |
| `?.` | 左值为 null/undefined 时整体短路为 undefined，不抛错 |
| `??` vs `\|\|` | `??` 只认 null/undefined；`\|\|` 连 `0`、空串、false 都算假 |
| `async` / `Promise` / `await` | Promise 是「以后会好的值」；await 等待但不阻塞线程 |
| `for…of` / `=>` / `${}` | 遍历值、箭头函数、模板串 |
| `T[]` / `ReadonlySet<T>` | 数组写法、只读集合 |

讲某个符号时，**绑在它所在的那一行真实代码上**，不要脱离上下文列语法字典。

## 渲染页面

1. 先判断 CLI 可用性：在 answer-me-with-html 插件的 cache 目录下找最新版本的 `scripts/am.mjs`。可用则走页面；不可用（无 Node 20+、无该插件、或 Codex 环境）则按上面的结构输出结构化 Markdown 文本，并在开头说明「未生成页面，原因是 X」。
2. **草稿先落文件再渲染**：把完整草稿写入 `$TMPDIR` 下的 `.md`，再 `am render <文件>`。长草稿不要用 heredoc 传——会被截断并报 `fenced block is not closed`。
3. 渲染报错时按 `L<行号>` 修草稿文件后重跑；已有页面用 `--replace <旧页面路径>`。
4. 页面语言与用户提问语言一致；中文用 `lang: zh`。
5. 结构复杂（≥3 个板块）时用 `template: doc`；短小主题用默认 sheet。

## 库函数

只说明代码直接调用的第三方库或标准库函数，不展开库内部实现。

每个函数简述来源、作用、关键参数和返回值。参数具有有限枚举值时，逐项说明各值的含义，不只罗列名称。

优先根据本地依赖版本、类型声明和文档核实行为。需要查外部资料时使用当前可用的搜索能力和官方文档；无法核实的版本差异或动态行为明确标为不确定，不猜测。

## 输出与边界

- 终端回复只给 2–3 行：一句核心结论 + 页面链接；不复述页面内容。
- 说明副作用、边界条件和明显错误。发现 bug 时指出位置和影响，未经用户要求不修改或重构源码。
- 引用到的每个 `file:line` 必须本轮核实过；核实不了就写「未核实」，不猜。
