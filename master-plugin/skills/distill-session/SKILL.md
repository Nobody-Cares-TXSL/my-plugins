# distill-session — 会话摩擦蒸馏

复盘当前会话，把调用插件时遇到的摩擦提炼成可执行的优化清单。

## 输入与工具

- Claude Code CLI：从 `$ARGUMENTS` 读取可选聚焦范围；复盘当前会话上下文；用 Read、Bash 取证；用 AskUserQuestion 确认修复项。
- Codex：从用户消息读取范围，不依赖 `$ARGUMENTS` 自动展开；使用当前环境提供的读写与命令执行工具；确认使用支持审批的工具或直接在对话中询问，没有回复就等待，不将默认选项或超时视为同意。

## 核心判据：摩擦的三方归类

会话里的摩擦**不等于插件问题**。必须归类，否则会把模型或环境的账算到插件头上，改错方向。

| 类型 | 特征 | 例 | 处理 |
|------|------|-----|------|
| **插件问题** | 脚本行为错、文档与实现不符、配置缺失、路径失效 | 脚本误删链接、文档版本号过期、缺步骤 | 进入优化清单 |
| **模型问题** | agent 输出格式错、理解偏差、幻觉、猜测参数 | 工具调用格式残缺、凭空编参数值 | 只报告，不改插件 |
| **环境问题** | 外部依赖故障、网络、版本冲突 | 镜像源 403、依赖跨大版本不兼容 | 只报告，可能需改配置 |

归类依据必须是**证据**（报错原文、脚本行号、实测结果），不接受主观感受。

## 改进维度：插件问题 → 改哪里

归类为插件问题后，逐维度过一遍。维度按**后果严重度**排序——越靠前，误判代价越大。

| 维度 | 问什么 | 证据 |
|------|--------|------|
| **破坏性操作** | 脚本里的 `rm`、覆盖、差集，作用域是否被限定？误伤面多大？ | 脚本行号 + 实测 |
| **跨清单一致性** | Claude 与 Codex 的 `plugin.json` 版本号、技能列表是否同步？ | 两文件对照 |
| **文档-实现漂移** | SKILL.md 的步骤、路径、版本号 vs 脚本实际行为是否一致？ | 逐条对照 |
| **触发精度** | description 在该触发时触发了吗？不该触发时误触了吗？ | 会话中的触发记录 |
| **上下文经济** | SKILL.md 是否过长？该渐进披露到 `references/` 吗？ | `wc -l` |
| **指令有效性** | 有没有不改变模型行为的 no-op 指令？ | 对照默认行为 |
| **能力失效** | 该能力还有人用吗？该退役还是重估？ | 跨会话转录的调用频次 |

优先**确定性守卫**（限定作用域、加校验）而非提醒类措辞——守卫每次运行都生效，提醒只对读到的人生效。

每维度给出具体改进项，**按后果严重度排序**输出（误删 > 漂移 > 冗余），不看修复难度。

## 执行流程

### 1. 收集摩擦

摩擦不一定留下显性信号。分两类找，**隐性那类才是主要盲区**。

**显性摩擦**（已发出信号）：

- 工具调用失败、报错、重试
- 用户重复解释同一件事
- 被迫绕过——试过插件、失败了，用户自己补上

**隐性摩擦**（无显性信号，靠证据推）：

| 形态 | 特征 | 指向 |
|------|------|------|
| 未触发 | 用户手动做了插件该做的事，全程没提插件 | 触发精度 |
| 成本异常 | 调用成功了，但 token/往返/耗时明显偏高 | 上下文经济 |
| 行为漂移 | 用户不再请求某能力、改用替代方案、措辞自我限定 | 能力失效 |

**证据源不止用户话语**：本次会话的**工具调用轨迹**（哪些报错、重试、往返几次、token 多少）模型可直接读到，比回忆用户语气可靠。隐性摩擦常跨会话才显形，需查转录：

```bash
# 当前会话转录（${CLAUDE_SESSION_ID} 由 Claude Code 注入）
rg -n '<关键词>' ~/.claude/projects/*/${CLAUDE_SESSION_ID}.jsonl
```

> 转录里 `type: "user"` 不等于用户发言：需排除 `isMeta: true` 与工具结果（`content` 为 tool_result）。

### 2. 三方归类

逐条归类，每条附证据。归为模型/环境问题的不进优化清单。

### 3. 报告清单

输出「摩擦 → 归类 → 维度 → 证据 → 建议」表，插件问题排最前；同类插件问题按后果严重度排序。

### 4. 询问是否修

用 AskUserQuestion 让用户勾选要修的项。**不自动修**——归类可能有误，用户最清楚实际影响。

### 5. 修复（走证据优先流程）

对选中的项：

1. **取证** — `rg -c`、`wc -l`、`git log` 确认问题真实存在
2. **证伪** — 查运行日志、实测一次、对照测试，排除伪问题（可能上次已修）
3. **分级** — 零风险项（结果不变）直接做；行为变更项先确认
4. **验证** — 每项改完立刻 `bash -n` + 实测；能加确定性守卫的（限定作用域、加校验）优先加守卫，别只改措辞
5. **收尾** — 同步文档 → 双清单 bump 版本 → 提交推送 → 更新本地

收尾约定见 `../update-my-plugins/SKILL.md`。

## 输出格式

```
| # | 摩擦（现象） | 归类 | 维度 | 证据 | 建议 |
|---|-------------|------|------|------|------|
| 1 | 差集误删独立 skill 的符号链接 | 插件 | 破坏性操作 | update-opencli.sh:59 差集未限定域 | 限定 opencli 生态 |
| 2 | 两清单版本号不一致 | 插件 | 跨清单一致性 | plugin.json 与 codex-plugin.json 不同步 | 同步 bump |
| 3 | 手动改了 README 而非触发 sync-statusline | 插件 | 触发精度 | 全程无插件调用记录 | 补触发词 |
| 4 | 工具调用格式残缺，重试 3 次 | 模型 | — | 转录中 3 条 tool_use 报错 | 无需改插件 |
| 5 | 镜像源 HTTP 403 | 环境 | — | 报错原文 | 换镜像源 |
```

## 注意

- 归为**模型/环境问题的不改插件**，只报告。
- 插件问题也要先证伪——可能上次已修复，或查证后发现机制正常。
- 只碰摩擦直接指向的代码，不做超范围改动。
